# Decisions

Choices made where the spec was unclear or had a gap. Newest at the bottom.

| ID | Decision | Why |
| --- | --- | --- |
| D-001 | **MongoDB Atlas + Mongoose** instead of PostgreSQL + Prisma. | Owner provided a MongoDB Atlas database. Prisma's MongoDB support lags (no migrations, not in Prisma 7), Mongoose is the mature option. Atlas runs as a replica set, so multi-document transactions are available. |
| D-002 | **Auth key / wrap key split.** Client derives `masterKey = Argon2id(password, kdfSalt)`, then `authKey = HKDF(master, "auth")` (sent to API, stored as argon2 hash) and `wrapKey = HKDF(master, "wrap")` (wraps the vault key, never leaves the device). New endpoint `POST /auth/prelogin` returns `kdfSalt` + `kdfParams`. | In the spec the plain password was sent to the API *and* used to wrap the vault key, so the API could unwrap every secret. |
| D-003 | `prelogin` for an unknown email returns a deterministic fake salt (`HMAC(SERVER_SECRET, email)`). | Avoids revealing which emails have accounts. |
| D-004 | Password reset is two calls: `POST /auth/reset-password/verify {email, code}` → `{resetToken, vaultKeyRecovery}`, then `POST /auth/reset-password {resetToken, new keys, secretsReset}`. | Client needs `vaultKeyRecovery` to unwrap with the recovery key *before* re-wrapping with the new password. |
| D-005 | Reset without recovery key (`secretsReset: true`): API clears `secretEnc`/`passphraseEnc` on all servers, bumps `vaultKeyVersion`, stores the new `vaultKeyRecovery`. Any reset/password change revokes all refresh tokens and bumps `tokenVersion`. | Old devices still hold the old vault key; forcing re-login makes them fetch the new one. |
| D-006 | Reset code: 6 digits, 15 min, **max 5 attempts**, stored as HMAC-SHA256. A new request invalidates older codes. | 6 digits = 1M combinations; attempt cap stops brute force. |
| D-007 | Refresh tokens: opaque random, stored as SHA-256, **rotation with reuse detection** (reusing a rotated token revokes its whole family). | Detects stolen refresh tokens. |
| D-008 | Access JWT carries `tv` (user `tokenVersion`); `requireAuth` loads the user and rejects stale versions. | "Log out everywhere", password change and account delete take effect immediately, not after 15 min. |
| D-009 | Password change is `POST /me/password` (not `PATCH /me`); it re-wraps the vault key and returns fresh tokens for this device. Email change needs `currentAuthKey`. Account delete needs `authKey`. | Sensitive changes need re-auth; password change must carry a new `vaultKeyWrapped`. |
| D-010 | Rate limits are in-memory (single API instance). Login/reset: 10 per 15 min per IP + email; signup: 10 per hour per IP. | MVP runs one instance; switch to a Redis store when scaling out. |
| D-011 | Sync cursor is a **per-user** `syncSeq` counter on the User document, incremented inside the push transaction. | A global sequence can commit out of order, which makes clients skip changes forever. Incrementing one document per user also serializes concurrent pushes of that user. |
| D-012 | Conflicts compare `clientUpdatedAt` (device clock), not the server's `updatedAt`. `lastConnectedAt` merges as max and `hostKeyFingerprint` as latest, outside conflict detection. | Server `updatedAt` only says who pushed last. Connecting must not cause conflicts. |
| D-013 | Push is idempotent through a client `mutationId` per change. | A lost response followed by a retry would otherwise look like a conflict. |
| D-014 | A server `id` that belongs to another user is rejected with `ID_CONFLICT`. | Client-made UUIDs must not let one user overwrite another's record. |
| D-015 | Purge after 30 days keeps a tombstone (id, seq, purgedAt) and clears content; pull returns it in `purgedIds`. Because tombstones are never deleted, no "resync required" path is needed. A device that still has a purged server and edits it brings it back. | Devices offline for >30 days must still learn about deletions. |
| D-016 | All crypto and the sync engine run in the **Electron main process**. The renderer reads servers from local SQLite via IPC and never holds the vault key or plain secrets. API calls come from main, so CORS only matters for development. | Removes the spec's conflict between "UI fetches from API" and "offline-first local copy". |
| D-017 | Vault key is kept in `safeStorage` with the refresh token, so "stay logged in" doesn't ask for the password on each start. | Spec didn't say how the vault unlocks after a restart. A "lock vault" option can come later. |
| D-018 | Terminal tabs live in one always-mounted `/deck` shell (tabs in Zustand), not a `terminal/[tabId]` route. | Static export can't serve runtime dynamic routes, and switching routes would unmount live terminals. |
| D-019 | Export file is encrypted with a passphrase the user enters at export time (Argon2id + AES-GCM). | Spec didn't say which key; a passphrase makes the file usable across accounts. |
| D-020 | ssh2 uses `tryKeyboard: true` and keepalive of 15 s. PuTTY `.ppk` keys aren't supported in v1. | Many servers offer password auth only as keyboard-interactive. |
| D-021 | Shared package ships TypeScript source (no build step); the API is bundled with tsup, Electron main with esbuild (D-028), Next.js uses `transpilePackages`. | One less build step; types never drift. |
| D-022 | In development without SMTP settings, reset codes are written to the API log. In production, `SMTP_HOST` is required. | Lets you test the reset flow locally without a mail server. |
| D-023 | Local cache uses Node's built-in **`node:sqlite`** (Electron 44 ships Node 24) instead of better-sqlite3. | better-sqlite3 needs a native rebuild per Electron version (C++ build tools on Windows). The built-in module needs nothing and also runs in plain Node for tests. |
| D-024 | Sync runs every **55 s** (plus on start, focus, and 0.5 s after a local edit). | With exactly 60 s, request time can push "visible on the other device within 60 s" just over the limit (measured 58 s in the acceptance run). |
| D-025 | History restore is `POST /servers/history/:historyId/restore`; trash restore stays `POST /servers/:id/restore`. | The spec used one path for both; separate paths keep the ids unambiguous. |
| D-026 | Set `SERVERDECK_USER_DATA` to run the app with a separate profile folder. | Lets two "devices" run on one PC for sync testing. |
| D-027 | On Windows/Linux, while a terminal has focus, Ctrl+K/N/W go to the shell; Ctrl+Shift+K/N/W do the app action there (they work everywhere). Outside the terminal, and with Cmd on macOS, the spec's shortcuts apply. Ctrl+C copies when text is selected, otherwise sends ^C; Ctrl+Shift+C/V and right-click also copy/paste. | Ctrl+W (delete word), Ctrl+K (kill line) and Ctrl+N (next history) are core shell keys; taking them would break terminal use. |
| D-028 | Electron main is bundled with esbuild (`scripts/build-electron.mjs`), including ssh2; all desktop packages are devDependencies. The API URL is set at build time with `SERVERDECK_API_URL`. | The installer then needs no `node_modules`, which avoids pnpm/electron-builder issues; app.asar is ~5 MB. |
| D-029 | "Test connection" asks about unknown host keys the same way as a real connection, before any credentials are sent. | Testing must not send a password to an unverified server. |
